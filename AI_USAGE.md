# AI_USAGE.md — Q-Day Rescue Run

Disclosure for the **Best AI-Native Build** special award and for judges who
want to know exactly what a human decided and what an AI generated.
Nothing in this file is aspirational: if it says a command was run, it was run,
and its output is quoted.

## Workflow in one paragraph

A human set the goal and the constraints; an AI agent (Muse, running as the
developer "Mica") researched the festival and the QoreChain stack, proposed the
game concept from a documented competitor-gap analysis, wrote the contract,
tests, frontend, deploy script and documentation, executed the test suite and
builds itself in a terminal, and reported failures with their exact errors.
The human reviewed direction at the level of *which project, which category,
what quality bar* — the standard demanded was "10/10, no defects, not basic".

## Step by step

### 1. Research (AI-executed, human-directed)

- Read the festival site (build.qorechain.io: homepage, /rules, /start, /kits,
  /about, /terms, /privacy) and the festival docs on docs.qorechain.io.
- Read the QoreChain SDK / EVM / PQC documentation and inspected the installed
  type definitions of `@qorechain/sdk` 0.14.0 and `@qorechain/evm` 0.14.0 before
  writing any integration code (this is how the exact `fetchPqcStatus`,
  `pqcKeyStatus`, `NETWORKS.testnet` signatures in `frontend/src/lib/qore.ts`
  were obtained — from the packages' own `.d.ts`, not from memory).
- Verified live chain state with direct API calls: EVM chain ID `0x2648` (9800),
  active precompiles (0x0901 / 0x0A01 / 0x0A02 / 0x0C01), Cross-VM allowlist,
  abstract-account config.
- Analysed 15 competitor projects from the festival feed + their GitHub repos
  to find the quality bar and the saturated ideas (certificate, checker,
  coin-flip, tip jar) that this project deliberately avoids.

### 2. Concept (AI-proposed from the gap analysis, human-approved direction)

The "5 missions = the real migration sequence, with scoring on-chain" concept,
including the phishing mission that *fails when approved*, was proposed by the
AI from two documented facts: (a) no existing Quantum Pass entry combines game
+ checker + certificate elements into a curriculum, and (b) festival rules
require a hybrid-signed transaction and testnet deployment, which the mission
order mirrors exactly (register key → window → hybrid transfer → KEM key).

### 3. Foundation spike (AI-executed before this project existed)

Before writing project code, the AI ran a separate spike (kept outside this
repo): cloned the official `qorechain/build-before-qday` examples, ran the
official Workshop 1 counter tests (2 passing), scaffolded a
`create-qorechain-dapp` 0.14.0 app and built it, created a throwaway testnet
account with the SDK, and attempted PQC registration — which produced the
documented, expected blocker "account does not exist on chain yet: send it some
QOR first", confirming the faucet-first bootstrap order used in the README.

### 4. Code generation (AI-written, compiler- and test-verified)

| Artefact | Generated by AI | Human contribution |
|---|---|---|
| `contracts/RescueRun.sol` | Full draft: bitmap progress, custom errors, phishing gate, badge struct | Quality bar + the locked concept (badge = record, not NFT) |
| `test/RescueRun.test.ts` | All 18 tests incl. negative cases | Requirement: ≥12 tests, negatives mandatory |
| `frontend/` (missions content, demo logic, `qore.ts`) | Full implementation | Concept + "demo must work fully without chain" constraint |
| `scripts/deploy.ts`, configs | Full implementation | — |
| `README.md`, this file | Drafted by AI from the actual command outputs | Final review responsibility |

### 5. Verification (AI-executed, outputs recorded)

Every claim in the README traces to a command the AI actually ran in this repo:

```bash
npm install          # root: 636 packages, exit 0
npm test             # solc 0.8.24, "18 passing", exit 0
npm run typecheck    # tsc --noEmit, exit 0
cd frontend && npm install   # 144 packages, exit 0
npm run build        # tsc --noEmit && vite build, exit 0 (chunk-size warning noted in README)
```

Known non-fatal findings the AI surfaced instead of hiding: the pre-0.14.0
official examples lag one SDK version; the frontend bundle is ~2.9 MB pre-gzip
because the SDK pulls CosmJS; deployment is blocked on the sign-in-gated faucet
(24 h cooldown) — all recorded in the README's *Honest limits*.

## What the AI did NOT do

- Did not register for the festival, create any account in the human's name, or
  submit anything.
- Did not touch the human's GitHub/QoreX credentials or the spike account's
  secrets (`.secrets/`, never read into this repo, never committed).
- Did not deploy to testnet: no funded account exists yet, and the AI reported
  that blocker instead of fabricating a contract address or tx hash.
- Did not copy competitor code; contract and UI are original (the only borrowed
  patterns are the festival's own documented bootstrap order and SDK APIs).

## How a judge can verify this disclosure

1. `git log` / file timestamps show the build order: spike → contract → tests → frontend → docs.
2. Re-run the commands in §5 — outputs must match.
3. Every external fact in the README (endpoints, precompiles, SDK versions,
   faucet behaviour) can be re-checked against docs.qorechain.io and the live
   REST API at https://api-testnet.qore.host.
